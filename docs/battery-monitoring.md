# Battery monitoring

The shared device model reserves optional aggregate, transmitter, and receiver battery information. An empty value means telemetry is unavailable or has not been investigated; it never means 0%.

## Linux Bluetooth

PipeWire can report a Bluetooth source address using its `api.bluez5.address` property. When that address is available, ClearMic asynchronously queries BlueZ's read-only `org.bluez.Battery1.Percentage` property, matches the Bluetooth address to the BlueZ device object path, and shows the reported percentage. It refreshes the cache at most every 30 seconds and discards readings older than 60 seconds; missing D-Bus service, missing property, malformed percentage, or missing address remains unavailable. BlueZ's Battery1 API supplies a percentage, not charging state, so ClearMic does not infer charging from it. This uses OS-provided telemetry, not a vendor guess ([PipeWire key reference](https://docs.pipewire.org/group__spa__keys.html), [BlueZ Battery API](https://github.com/bluez/bluez/blob/master/doc/org.bluez.Battery.rst)).

## Windows and device limitations

Windows' `Windows.Devices.Power.BatteryReport` is for battery controllers enumerated by Windows and returns null properties when a value is absent; the aggregate report must not be attributed to a Bluetooth accessory ([Microsoft battery information guide](https://learn.microsoft.com/en-us/windows/apps/develop/devices-sensors/get-battery-info), [BatteryReport API](https://learn.microsoft.com/en-us/uwp/api/windows.devices.power.batteryreport)). For BLE accessories, the documented GATT client API can read the standard Battery Service only if that accessory exposes it ([Microsoft GATT client guide](https://learn.microsoft.com/en-us/windows/apps/develop/devices-sensors/gatt-client)). ClearMic does not yet have a Windows accessory battery backend.

On the Windows development machine, WMI exposes a system battery instance (`ACPI\\PNP0C0A\\1_0`) only; that value belongs to the laptop and is not assigned to any microphone or headset. The paired Sony WF-C710N has Windows Bluetooth/HFP/AVRCP PnP functions but no active WASAPI capture endpoint and no associated WMI battery instance. The USB receiver is `VID_3151&PID_3020`; Windows enumerates a composite USB device, mouse, consumer-control, keyboard/system-control, and vendor-defined HID collections. Standard PnP power properties contain no charge percentage. Its vendor-defined collection reports usage page `0xFF00`, usage `0x000E`; report descriptor/report IDs and input/feature data have not yet been captured. A different paired BLE device's Battery Service is not evidence for this headset. Values for the headset and USB wireless receiver therefore remain unknown, never copied from the laptop or another nearby device. Further read-only HID inspection is required before concluding that the receiver provides no telemetry.

BlueZ Battery1 gives one percentage for a Bluetooth device. It does not currently distinguish left/right earbuds, transmitter, receiver, or charging state. USB wireless transmitter/receiver values remain unavailable unless a documented OS or device report supplies them.
